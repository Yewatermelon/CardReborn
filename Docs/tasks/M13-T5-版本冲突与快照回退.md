## 2. 目标（一句话）

> 客户端遇到版本空洞（VersionGap）时可**主动请求全量快照**（`SnapshotRequest` → 按座位投影快照单播回端点），重置基线后与权威恢复一致；恢复后过期步自动丢弃、新步继续应用——**丢弃过期包；版本冲突时可恢复**（Docs/02 AC）。

## 3. 范围（做什么）

- **上行新 kind `snapshot_request`**：`{"kind":"snapshot_request","version":<本地版本>}`（§9.1 SnapshotRequest 携带本地版本号）。宿主在 `MatchHost.ProcessOne` 增加分支，**复用 hello 快照路径**（按端点座位投影 + 当前权威版本），**单播**回请求端点（不广播、不结算、不进命令校验链）。
- **`ClientStateSync.BuildSnapshotRequest(ulong localVersion)`**：请求构造器（纯函数，客户端循环/T7 重连复用）。
- **恢复流程测试固化**（客户端侧规程）：`ApplyStep` 返回 `VersionGap` → 发 `BuildSnapshotRequest(LocalVersion)` → 收快照 → `ApplySnapshot` 重置基线（T4 已支持重复调用 = 重置）→ 此后 gap 期间积压的旧步按 T4 规则自动 `DuplicateDiscarded`（version ≤ 本地），新步正常 `Applied`。

## 4. 明确不做（防止范围蔓延）

- **TCP 帧化接线**（`NetworkMessageType.RequestSnapshot` + HostBridge/PeerSession 上行分支）：当前尚无客户端会话组件产生该帧，先行接线属投机实现——移交 M13-T7（掉线重连）与真实客户端路径一并落地（移交项 1）；
- **快照请求节流 / 防刷**（同端点连续请求风暴）——T9 异常注入矩阵评估；
- **ReconnectRequest / 掉线窗口 / 超时判负**——T7、T8；
- **定期轻量校验包**（§5.4 每 N tick 版本 + 摘要）——非本任务；
- 快照差量/压缩——状态体积小（§5.2），不优化。

## 5. 接口约定

```csharp
// 上行（C→S，Loopback / 未来 TCP 帧）

```

**设计决策登记**：
1. **宿主对 `snapshot_request` 的 version 字段只记录不裁决**：快照总回"当前权威版本 + 当前全量状态"——请求方版本号用于日志与将来的诊断（§9.1 语义），不据此做差量（状态体积小，§5.2）。
2. **快照请求与 hello 共用同一下行路径**（`SendSnapshot`）：同座位投影、同版本标注、同单播语义；hello 即"隐式快照请求"。
3. **恢复规程由测试固化而非组件内嵌**：ClientStateSync 保持纯状态机（不持有网络引用），VersionGap → 请求 → 重置的编排由客户端循环/调用方执行（T7 重连复用同一规程）——符合铁律 12（网络代码只在 Card.Network）与依赖向下。
