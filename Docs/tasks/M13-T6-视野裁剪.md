## 2. 目标（一句话）

> `PlayerViewProjector` 从 identity 落地为真实裁剪：**对手手牌只留数量与背面标识、牌库（含自己的）顺序与内容不下发**，快照与增量（每座位独立 step）全部经由裁剪——任一下发给玩家 2 的数据不含房主手牌明细与牌库顺序。

## 3. 范围（做什么）

- **`PlayerViewProjector.Project(state, seat)` 真实实现**：序列化往返深拷贝后按 §5.3 矩阵遮蔽——
  - 双方 `deck`：全部替换为背面占位卡（数量保留、顺序与内容抹除；自己的牌库同样遮蔽）；
  - 非 `seat` 的 `hand`：替换为背面占位卡（数量保留、内容抹除）；
  - `board` / `graveyard` / 英雄 / 法力：完整下发（公开信息）。
- **背面占位卡**：`CardInstance.Restore(id, PlayerViewProjector.MaskedCardKey, ownerId, 0, 0, 0, None, None, 0)`，**保留真实 InstanceId**（Diff 按 InstanceId 索引，数量增减自动同步；id 本身不泄露内容）。
- **MatchHost 每座位独立 step**：接受命令后按端点座位分别 `Diff(Project(before,seat), Project(after,seat))`，同版本/seq/accepted，各自单播；幂等收件箱按座位记录各自 step。拒绝 step（changes 为空）维持原广播。
- **事件不裁剪**：`CardDrawn/CardBurned` 等事件只含座位与 instanceId（无卡牌内容，已核对 EventSerializer），id 为不透明数字不泄露信息。

## 4. 明确不做（防止范围蔓延）

- **mulligan / 起手换牌的跨端点隐藏流程**——PVE 现流程为本地直改，PVP 起手交互归 M14 联机流程设计；
- **事件字段级遮蔽**（如把 CardDrawn 改写成"对手抽了一张牌"专用事件）——现事件不含内容，不需要；
- **观察者/观战座位**（seat ∉ {0,1} 的视图策略）——阶段二无观战；非法座位按"全遮蔽"保守处理（两位手牌都遮）；
- **裁剪后步数的性能优化**（每命令 2 次投影 + 2 次 Diff）——回合制量级无压力（§10 预算）；
- **牌库数量字段**（`deckCount`）——占位卡数量即数量，不新增协议字段。

**设计决策登记**：
1. **占位卡表示法**（隐藏信息进入统一状态管线）：隐藏分区以"真实 InstanceId + `__hidden__` 卡 Key + 零值属性"的占位卡填充——快照/增量/Differ/Applier 全链路零特判（Differ 按 InstanceId 索引，数量增减自动同步）；代价是 InstanceId 本身下发（不透明数字，不泄露内容）。
2. **每座位独立 step**：接受命令后按座位投影 before/after 并各自 Diff——投影后 Diff 自动消灭"对手手牌增益"等泄露性变化（占位卡前后一致 → 无变化）；拒绝步 changes 为空维持广播。
3. **事件不裁剪**：事件载荷仅含座位与 instanceId（不透明），无需改写；未来若事件携带卡牌内容再引入按座位事件过滤（登记于 Docs/05 复盘候选）。
4. **测试基建**：共用夹具助手 StateSyncTestHarness（对局构造/信封/步收取/StepForSeat 座位副本选择），后续 M13-T7/T9 与 M14 测试复用。
