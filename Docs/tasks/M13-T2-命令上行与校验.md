## 2. 目标（一句话）

> 权威宿主对上行 Command 做信封级校验（载荷可解析 + 座位归属），非法命令产出**结构化拒绝**（error + detail）且回传、状态零变更、宿主不因坏包抛异常。

## 3. 范围（做什么）

- `MatchHost.ProcessCommand` 增加信封级校验（即 Docs/05 §3.4 `CommandValidator` 职责，由 MatchHost 承担，规则级校验仍唯一经 `RuleEngine`/`MatchController.Submit`，避免双份校验源）：
  - **载荷校验**：command 消息缺 `payload`、payload 非法 JSON、未知命令类型标签、缺必需成员 → 结构化拒绝（`UnknownCommand` + detail），不再抛 `FormatException`/`ArgumentException` 打死宿主；
  - **座位归属校验**：命令归属玩家（`command.PlayerId`）与端点绑定座位（`Attach` 记忆值）不一致 → 结构化拒绝（`NotYourTurn` + detail 含"座位"）。不引入独立信封 seat 字段——`IGameCommand.PlayerId` 即座位身份（其契约注明"来源座位由 PlayerId 自证"），信封 seq 字段归 T3。
- **拒绝原因结构化**：step 消息新增 `detail` 字段（`CommandResult.Detail`；接受时为空串），`error` 字段维持枚举名字符串（协议兼容）。
- 拒绝 step 沿用 M11 广播形态（`accepted=false` + `error` + `detail`），专用 `CommandRejected` 帧与单播语义归 T4 下行重构统一决策。
- 顺带完成 **M13-OBS-1**：把 `PeerSession` 从 `PeerHost.cs` 拆分为独立文件 `PeerSession.cs`。
- 同步更新 M11 时代测试至 M13 座位语义（见第 7 节）。

## 4. 明确不做（防止范围蔓延）

- 命令序号 / 幂等去重 / 越权之外的重放识别 —— **T3**；
- `StateDelta{basedOn}` / 专用 `CommandAccepted`/`CommandRejected` 帧型 / 拒绝单播 —— **T4**；
- 快照回退 —— T5；真实视野裁剪 —— T6；掉线重连 —— T7；异常终态 —— T8；异常注入矩阵 —— T9；
- 客户端 UI 拒绝提示（M6-B3，M9/M14）；
- 速率限制 / 频率防刷（Docs/05 §7.3 属未来加固，本阶段明确不做反作弊）。

**设计决策登记**（待确认问题→已裁决）：
1. **座位身份以 `IGameCommand.PlayerId` 为准**，不引入独立信封 seat 字段——`PlayerId` 即座位身份（接口契约"来源座位由 PlayerId 自证"），信封字段扩充（seq）统一归 T3，避免 T2/T3 两次改协议。
2. **`CommandValidator` 职责由 MatchHost 承担**（Docs/05 §3.4 的类清单落地形态）：信封级校验在宿主入口，规则级校验唯一经 `RuleEngine`（经 `MatchController.Submit`），无双份校验源。
3. **拒绝沿用 step 广播形态**（M11 兼容），单播/专用帧归 T4 下行重构统一决策。
4. **seed 42 先手实为座位 0**（非此前记忆的 1）——网络测试剧本改为"房主本地端点先行 + 对手跟上"双腿剧本，座位一律动态读取（遵循"不硬编码先手"教训）。
