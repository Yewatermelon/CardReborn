## 2. 目标（一句话）

> 所有异常路径都有**明确终态**：对局内任何权威状态变更（含掉线判负、回合超时代发结束回合）统一经 `MatchHost.SubmitAuthority` 走"校验→结算→终局判定→step 下发"既有链路；对局结束时主机向对手下发 `MatchEnd { winner, reason }` 帧；房主中途退出时尽力通知对手（HostQuit）后关闭——不无限等待、不假活。

## 3. 范围（做什么）

- **`ForfeitCommand`（规则层新增命令）**：判负命令——判负者英雄生命置 0，由 `MatchEvaluator` 统一判定对手胜（终局判定入口唯一，结算器不写终局）。注册三处：`GameCommands.cs`（readonly struct）、`CommandSerializer`（`"Forfeit"` 序列化/反序列化）、`RuleEngine.Validate`（特例分支）。
- **RuleEngine 特例校验**：`ForfeitCommand` 只要求座位存在，**不要求当前回合 / Main 阶段**（掉线判负场景中掉线方可能非行动方）；对局已结束后仍拒绝。置于座位存在性检查之后、回合/阶段检查之前。
- **`ForfeitSettler`（2_Application）**：把判负者英雄生命置 0；`MatchController` 构造函数注册。终局 reason 为既定文案（英雄生命归零），网络层原因语义由 MatchEnd 帧补足。
- **`MatchHost.SubmitAuthority(IGameCommand)`**：权威内部管理动作入口（掉线判负代发 Forfeit、回合超时代发 EndTurn）——不走端点座位校验与 seq 收件箱（权威自己的决定，非客户端意图），但复用 `SubmitAndBroadcast` 完整链路：RuleEngine 校验 → 结算 → 每座位裁剪 step 下发 → version 推进。随 `ActiveSeat`、`Outcome` 两个只读属性放入 partial 文件 `MatchHost.Authority.cs`（主文件已 283 行，铁律 10 单文件 ≤300 行）。
- **`PeerHost.RunNetworkTick` 终态编排**（ManualClock 可测，10 Hz tick 口径）：
  - **回合操作超时 75 s**（750 tick）：`StateVersion` 不变持续 ≥750 tick 且对局进行中 → `SubmitAuthority(EndTurnCommand(ActiveSeat))` 自动结束回合；version 变化即重置计时（口径：75 s 内无任何权威状态变更即代发，含房主自己不动的情况，与 §8.2 一致）；
  - **掉线判负 30 s**（300 tick）：会话 `IsConnected == false`（心跳超时或 TCP 断开）且对局进行中 → 起计时；持续 ≥300 tick 未重连 → `SubmitAuthority(ForfeitCommand(掉线座位))`；`AcceptPeer` 新会话即取消计时（重连恢复由 T7 机制驱动）；
  - **MatchEnd 帧**（`NetworkMessageType.MatchEnd = 20`，载荷 `{ "winner": N|null, "reason": "..." }`）：对局已激活且 `IsFinished` 且未发过 → 经 `HostBridge.SendMatchEnd` 下发给对手；reason ∈ `Normal`（正常终局）/ `Disconnect`（掉线判负后终局）/ `HostQuit`（房主退出作废）。
- **`PeerHost.Dispose` 终态**：对局已激活且未结束时 Dispose → 尽力向对手发 `MatchEnd(null, "HostQuit")` 后关闭监听（传输已断则跳过，不抛异常）。
- **新增 PeerHost 常量**：`TurnTimeoutTicks = 750`、`ReconnectWindowTicks = 300`。

## 4. 明确不做（防止范围蔓延）

- **玩家主动投降 UI 入口**——M14-T6（ForfeitCommand 本任务只建立机制，权威代发路径打通）；
- **客户端 MatchEnd 帧的 UI 处理**——M14-T6 异常体验打磨（客户端收到未知 S→C 帧已有"记录并忽略"行为，不崩）；
- **消息异常注入矩阵**（畸形帧 / 越界类型 / 超大载荷）——M13-T9；
- **双方同时掉线作废**——单一对手会话模型下无"双方"，阶段三多对局再议（§8.2 该行为登记待定）；
- **回合超时判负配置化**——§8.2 "可配置为判负"不做，固定自动结束回合；
- **主机迁移**（房主退出后对手接管）——§Q-5b 未定 P2，房主退出即对局作废。

## 5. 接口约定

```csharp
// 1_Domain：GameCommands.cs（只加不删）
public readonly struct ForfeitCommand : IGameCommand { public int PlayerId { get; } }

// CommandSerializer：type 标签 "Forfeit"（无额外字段）
// RuleEngine.Validate：座位存在 → ForfeitCommand 直接 Valid（回合/阶段豁免）

// 2_Application：MatchHost.Authority.cs（partial MatchHost）
public CommandResult SubmitAuthority(IGameCommand command);  // 权威内部动作：无座位/seq 校验
public int ActiveSeat { get; }                               // 代理 controller.View.ActivePlayerId
public MatchOutcome? Outcome { get; }                        // 代理 controller.LastOutcome

// 2_Network：HostBridge
public void SendMatchEnd(int? winner, string reason);        // MatchEnd=20 帧

// 2_Network：PeerHost 常量与编排
public const int TurnTimeoutTicks = 750;       // 75 s @ 10 Hz
public const int ReconnectWindowTicks = 300;   // 30 s @ 10 Hz
// RunNetworkTick：泵会话/权威/桥接（现有）→ 版本推进重置回合计时 → 回合超时代发
//   → 掉线计时/判负 → MatchEnd 下发（一次性）
```

## 6. 验收标准（必须可测）

| 编号 | 场景 | 期望结果 |
| --- | --- | --- |
| AC-1 | Forfeit 判负与终局 | 非行动方座位 Forfeit → 有效（回合/阶段豁免）：判负者英雄生命 0、对手胜、`IsFinished`、事件含 `MatchEndedEvent`；对局结束后任何命令被拒 |
| AC-2 | Forfeit 序列化往返 | `Serialize/Deserialize` 等值往返；未知类型标签行为不变 |
| AC-3 | 回合超时自动结束回合 | 开局后 ManualClock 快进 750 tick 不发命令 → RunNetworkTick 后权威 version +1、行动方切换；快进不足 750 tick 不触发；version 推进后计时重置（不会连续代发） |
| AC-4 | 掉线判负 | 开局后断开对手 TCP → 快进 300 tick → 对局结束（判负方座位 1）、对手收到 StateDelta（判负 step）与 MatchEnd `{ winner: 0, reason: "Disconnect" }`；快进不足 300 tick 不触发；重连（AcceptPeer）取消计时 |
| AC-5 | 正常终局 MatchEnd | 权威代发路径（`SubmitAuthority(ForfeitCommand)`）触发终局后未标记 Disconnect 时，对手收到 MatchEnd `reason: "Normal"`；只发一次 |
| AC-6 | 房主退出终态 | 对局进行中 `PeerHost.Dispose` → 对手尽力收到 MatchEnd `{ winner: null, reason: "HostQuit" }`；Dispose 幂等不抛异常 |
