## 2. 目标（一句话）

> 会话层（PeerSession）对所有异常上行消息——状态机乱序（未握手 Ready）、重复握手、版本不匹配、S→C 专属类型上行、未知类型、畸形帧——**全部拒绝且不崩溃**：可恢复的丢弃 + 告警，不可恢复的 framing 损坏走断链终态（掉线判负编排接管），宿主进程在任何注入下不抛异常、不假活。

## 3. 范围（做什么）

- **注入矩阵分层盘点（本任务先固化已防，再补齐空白）**：
  - 已防且有测试（不重做）：命令级乱序/重复/幂等（T3 seq）、StateDelta 版本乱序/重复/空洞（T4/T5）、HostBridge 上行畸形 JSON/未知 kind/缺 payload（T2 TryValidateUplink）、帧体长度畸形/超长（MessageCodecTests）、Hello 版本不匹配（握手测试）；
  - **本任务补齐（会话层 PeerSession 防御空白 + 测试固化）**：
- **PeerSession.Pump 畸形帧断链**：`TryUnframe` 抛 `ProtocolException`（长度前缀错位/framing 已坏——字节流无法恢复同步）→ 记日志 + 诊断 `ProtocolViolation` → `_transport.Dispose()` → 结束本帧处理（断链终态，PeerHost 掉线判负编排 M13-T8 接管）。**异常不得穿透 Pump**——宿主进程不崩。
- **PeerSession.Pump 统一版本门**：除 `Hello`（自带版本协商）外的所有上行帧，`ProtocolVersion != CurrentProtocolVersion` → 告警丢弃该帧（不断链——规格 §9.3 只定义握手版本协商，帧级版本字段为冗余防御，误杀代价高于收益）。
- **PeerSession.HandleReady 握手门**：未握手收到 `Ready` → 告警丢弃（修复假开局漏洞：当前实现会直接置 Ready 并发 MatchStart）。
- **PeerSession.HandleHello 重复握手幂等**：已握手再次收到 `Hello` → 告警忽略（不重发 HelloAck、不重复握手副作用）。
- **S→C 专属类型上行**（HelloAck / MatchStart / StateDelta / MatchSnapshot / MatchEnd / Error）：走既有 `default` 分支忽略 + 告警（行为已有，本任务测试固化）。
- **NetworkDiagnostics**：`NetworkEventType` 新增 `ProtocolViolation` 枚举值（只加不删）。

## 6. 验收标准（必须可测）

| 编号 | 场景 | 期望结果 |
| --- | --- | --- |
| AC-1 | 乱序·未握手 Ready | 握手前发 `Ready` → 丢弃（`PeerReady == false`、无 MatchStart 下发）；随后正常 Hello 握手仍可完成（会话未被破坏、不断链） |
| AC-2 | 重复·重复 Hello | 握手完成后再次发合法 `Hello` → 幂等忽略（对端收到的 HelloAck 仍只有 1 条）；后续 Ready 正常开局 |
| AC-3 | 版本不匹配·非 Hello 帧 | 握手后发 `Command` 帧带错误版本 → 丢弃（权威收不到、version 不推进）；同帧改回正确版本重发 → 正常处理（对端连接保持） |
| AC-4 | 非法字段·S→C 类型上行 | 对端向会话注入 `StateDelta` / `MatchStart` / `HelloAck` 帧 → 全部忽略 + 告警，连接保持、后续心跳正常 |
| AC-5 | 超长/畸形帧·断链终态 | 注入 framing 畸形帧（如帧体长度 < 5）→ `Pump()` 不抛异常、会话断开（`IsConnected == false`）、诊断含 `ProtocolViolation`、日志有记录 |
| AC-6 | 注入后宿主不崩溃不假活 | PeerHost 端到端（真实 TCP 回环）：依次注入未知类型、越座位 Command、版本错帧后 `RunNetworkTick` 不抛异常；合法命令仍走完"校验→结算→step 下发"链路 |
