## 2. 目标（一句话）

> 对局结束时自动生成可导出的 JSON 记录，包含对局 Id、时长、回合数、结束原因与命令流水，便于本机复盘排查。

## 3. 范围（做什么）

- 扩展 `MatchOutcome`（1_Domain/Match）：新增 `MatchId`（guid 字符串）、`StartTick`、`EndTick` 字段，使时长可由 tick 差 + 已知权威频率（10 Hz）计算
- 新建 `MatchRecord`（2_Application/Match）：聚合 `MatchOutcome` + `MatchStepRecord[]`（命令流水引用），提供 JSON 序列化往返
- `MatchController` 注入 `IClock`，构造时生成 guid 并记录 `StartTick`；终局时记录 `EndTick`，组装 `MatchRecord`
- `BattleSceneBootstrap`（含 Net 路径）监听对局终局，把 `MatchRecord` 写入 `Application.persistentDataPath/MatchRecords/<matchId>.json`
- 提供简单的导出入口（编辑器菜单 `Card/Export/MatchRecords`：打印目录路径；运行时无 UI，文件即导出）

## 4. 明确不做（防止范围蔓延）

- 不做游戏内 UI 展示对局列表或回放面板（阶段三元游戏内容）
- 不做命令流水的富事件还原（`MatchStepRecord` 已足够复盘；M4-T3 富事件家族不涉及）
- 不做服务端导出或云端同步（阶段二仅客户端本地）
- 不做加密、压缩或去标识化（本机验证环境无安全需求）
- 不做 PVE HotSeat 与 PVP 的记录格式差异（统一格式，结束原因区分）

## 11. 结论

### 11.1 交付清单

- `MatchOutcome`（1_Domain/Match）：新增 MatchId / StartTick / EndTick / DurationTicks；构造函数改 7 参数（Guard 校验 id/reason 非空）
- `MatchEvaluator`（2_Application/Match）：Evaluate 传 dummy id/0 tick——MatchController 终局时重新构造完整 MatchOutcome
- `MatchController`（2_Application/Match）：构造加 `IClock? clock = null`（可选参数，现有调用方零改动）；生成 guid MatchId、记录 StartTick；终局时组装 MatchRecord；新增 `MatchId` / `LastRecord` 只读属性
- `MatchRecord`（2_Application/Match，新建）：聚合 MatchOutcome + MatchStepRecord[] + PlayerNames + EndReasonNet
- `MatchRecordSerializer`（2_Application/Match，新建）：MatchRecord → JsonValue → JSON（Card.Core.JsonValue 纯 BCL）
- `MatchRecordPersister`（5_Bootstrap/Battle，新建）：persistentDataPath/MatchRecords/<matchId>.json 写盘；TrySave 防重
- `BattleSceneBootstrap`：Update 开头加 PersistMatchRecordIfNeeded 轮询（_controller.LastRecord != null && !_recordSaved）；EndReasonNet 从 _netLobby?.HostPeer?.LastMatchEndReason 取
- 测试：MatchOutcomeExtendedTests 4 例 + MatchRecordTests 3 例（EditMode/Match/，进 kernel）
- .meta × 2（MatchRecordSerializer、MatchRecordPersister，GUID 32 位全合规）

### 11.3 评审结论

- P0/P1：无。铁律自查：规则三层新增代码（MatchOutcome/MatchRecord/MatchRecordSerializer）纯 BCL；MatchController 新增 IClock 参数可选不破坏现有调用；表现层零改动；MatchRecordPersister 放 Bootstrap 层合理（Unity API + System.IO 只在这层）；单文件均 ≤300 行；0 warning。
- 假设登记：①MatchEvaluator.Evaluate 传 dummy id/0 tick——MatchController 是 MatchOutcome 真正持有者，终局时重新构造；②MatchController 构造函数加 IClock? 可选参数——现有夹具/调用方零改动（默认 null 回退 tick=0）；③联机异常终局（掉线判负）走 ForfeitCommand 正常流程，MatchController 仍组装 LastRecord；房主退出（HostQuit）在 PeerHost.Dispose 时发 MatchEnd，但 MatchController 可能已 Dispose——此路径 MatchRecord 可能缺失（P3，房主主动退出通常无需记录）。
- 遗留登记：无新增。AC-3 序列化往返——MatchRecordSerializer 只负责 MatchRecord → JSON，未实现 JSON → MatchRecord（本阶段只导出不复用，反序列化留阶段三）。
