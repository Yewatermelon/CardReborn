## 2. 目标（一句话）

> 上行 Command 信封支持**命令序号 seq**：权威宿主按座位独立识别重复包——重发只执行一次并**幂等重放**相同回执，过期/冲突序号**结构化拒绝且状态零变更**；step 回执回显 seq 供客户端对应请求。

## 3. 范围（做什么）

- **信封扩展**：`{"kind":"command","seq":N,"payload":{...}}`，N 为正整数（≥1），**按座位独立计数**；信封**缺 seq = 无序号模式**（维持 M11/T2 行为，兼容既有客户端与测试）。
- **序号规则**（每座位一个 `SeatCommandInbox` 收件箱，记录已消费最大序号 + 最近回执）：
  - `seq > LastSeq` → 执行（**允许跳号**：TCP 已保序，跳号不破坏幂等；严格连续会把客户端重传协议耦合死）；
  - `seq == LastSeq` 且 payload 原文相同 → **幂等回执**：不执行、不推进版本，定向重放缓存的 step 原文；
  - `seq == LastSeq` 且 payload 原文不同 → 拒绝 `StaleSequence`（"序号已被其他命令使用"）；
  - `seq < LastSeq` → 拒绝 `StaleSequence`（过期丢弃：不执行、状态零变更）。
- **seq 消费点**：座位归属校验通过、进入结算路径的命令（**无论接受或被 RuleEngine 拒绝**）都推进 LastSeq 并缓存回执——序号消费 = "处理过"而非"接受"；座位归属拒绝发生在序号校验之前，**不消费 seq**（冒用他人 PlayerId 不污染自己收件箱）。
- **step 回显 seq**：带 seq 命令的回执（含拒绝与幂等重放）带 `seq` 字段；无 seq 命令的回执不含该字段（协议向后兼容）。
- **错误码**：`CommandError` 按"只追加"原则新增 `StaleSequence`（对应 Docs/05 §9.1 CommandRejected 拒绝原因）。
- **顺带重构**：`MatchHost` 消息编解码（kind 读取/载荷解析/快照与 step 构造）拆分为 `MatchHostProtocol` 静态类——本任务新增逻辑后单文件将超 300 行铁律，提前拆分。

## 5. 接口约定

```csharp
// 信封：{ "kind":"command", "seq":N(可选,≥1), "payload":{...} }
// step：{ kind:"step", version, seq(仅当命令带 seq 时出现), accepted, error, detail, finished, changes[], events[] }

// SeatCommandInbox.cs（新文件，Card.Application.Match）：座位命令收件箱
public sealed class SeatCommandInbox
{
    public int LastSeq { get; }                       // 已消费最大序号，0 = 未消费
    public bool IsExecutable(int seq);                // seq > LastSeq（允许跳号）
    public bool IsRepeat(int seq);                    // seq == LastSeq > 0
    public bool MatchesLastPayload(string payloadJson);
    public void Record(int seq, string payloadJson, string stepJson);
    public string LastStepJson { get; }               // 幂等重放缓存
}

// MatchHostProtocol.cs（新文件）：从 MatchHost 拆出的无状态编解码
internal static class MatchHostProtocol
{
    public static string ReadKind(JsonValue json);
    public static bool TryReadCommand(JsonValue json, out IGameCommand? command, out string? error);
    public static JsonValue WriteSnapshot(MatchState state);
    public static JsonValue WriteStep(ulong version, int? seq, bool accepted, CommandError error,
        string detail, bool finished, IReadOnlyList<StateChange> changes, IReadOnlyList<GameEvent> events);
}

// MatchHost.ProcessCommand 校验链（追加第 ③ 段）：
//   ① TryReadCommand 载荷校验（T2） → ② 座位归属（T2，不消费 seq）
//   → ③ seq 字段合法性（存在但非数字/负数 → UnknownCommand）
//   → ④ 序号幂等裁决（过期/重复冲突 → StaleSequence；重复同载荷 → 重放；可执行 → 结算并 Record）
// CommandError 新增：StaleSequence（只追加，不改既有值）
```

## 6. 验收标准（必须可测）

| 编号 | 场景 | 期望结果 |
| --- | --- | --- |
| AC-1 | seq=1 命令被接受后**原样重发** | 第二次收到相同回执（accepted=true、seq=1、version=1）；`StateVersion` 不再增长；权威状态与执行一次后一致（只执行一次） |
| AC-2 | seq=2 命令被 RuleEngine 拒绝后**原样重发** | 相同 rejected 回执（accepted=false、error=NotYourTurn、seq=2）；状态不变——拒绝结果也可幂等重放 |
| AC-3 | 低序号重发（seq=2 已消费后发 seq=1 新载荷） | 拒绝 `StaleSequence`（detail 含"过期"）；状态零变更、版本不变 |
| AC-4 | 同 seq 不同载荷（seq=1 消费后换 payload 再发） | 拒绝 `StaleSequence`（detail 含"已被其他命令使用"）；状态零变更 |
| AC-5 | 跳号（首条即 seq=5） | 正常执行接受；此后 seq<5 一律过期拒绝 |
| AC-6 | 回执 seq 回显 | 带 seq 命令 → step 带 `seq` 字段；无 seq 命令 → step 无 `seq` 字段（既有行为回归） |
| AC-7 | seq 字段非法（负数 / 非数字） | 拒绝 `UnknownCommand`（信封级畸形）；状态零变更、不抛异常 |
| AC-8 | 双座位序号独立 | 座位 A 与座位 B 各自 seq=1 互不干扰（A 消费 seq=1 后 B 的 seq=1 仍可执行） |
| AC-9 | 座位归属拒绝不消费 seq | 冒用他人 PlayerId 被拒（T2 路径）后，同端点同 seq 的合法命令仍按"可执行"进入结算 |

**设计决策登记**（待确认问题 → 已裁决）：
1. **"越权命令拒绝"裁决**：T2 的座位归属校验（`command.PlayerId` vs 端点绑定座位）即 Docs/02 M13-T3"越权命令拒绝"的落地形态（端点只能以绑定座位身份发命令）；本任务不重复实现，"过期命令被丢弃"由 seq 过期拒绝覆盖。
2. **允许跳号**：seq 只要求对每个座位**严格单调递增**，不要求连续——TCP 已保证传输有序，跳号不影响幂等语义；严格连续会把客户端重传协议与权威实现耦合死。
3. **只对最近一条做幂等重放**：更早序号的重发一律按过期丢弃。TCP 保序下客户端"未收到回执而重发"的只可能是最近一条命令；维护全量已消费集合复杂度不值（本机验证阶段不做反作弊）。
4. **信封缺 seq = 无序号模式**：兼容 M11/T2 既有客户端与测试；本阶段无反作弊承诺，端点可自愿降级为无序号（登记为已知限制）。
5. **序号消费 ≠ 接受**：进入结算路径的命令无论接受/被拒都消费 seq 并缓存回执——否则被拒命令的重发会绕过幂等；座位归属拒绝在序号校验之前，不消费。
