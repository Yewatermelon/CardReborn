## 2. 目标（一句话）

> 把 M12-T8 预留的启动参数（`-host` / `-join`）接线到启动流程，配一键双开脚本与说明，使验证者按说明 5 分钟内跑起双人联机验证。

## 3. 范围（做什么）

- **参数接线**（核心）：`CommandLineRoleParser`（M12-T8 已交付但无生产调用方）接入启动流程——
  - 新增 `NetLaunch`（`2_Application/Launch/`，纯 BCL）：命令行参数 → 大厅自动动作（None / Host(port) / Join(address)）；端口未指定（0）映射为默认端口 7777（`PvpLobbyFlow.DefaultListenPort` 由调用方传入，保持 Application 层不依赖 Bootstrap）。
  - `MainMenuBootstrap.Start`：解析到 Host/Join → 直接设 `GameMode=PVPNet` 并载入 Battle 场景（跳过手动点击）。
  - `BattleSceneBootstrap.StartNetMode`：解析到 Host → 以参数端口构造大厅并自动 `CreateAsHost()`；Join → 自动 `ConnectAsJoiner(address)`；HotSeat → 现状不变（手动选择身份）。
  - 接线处 `GameLog` 记录启动角色，联机排障可从日志确认角色来源。
- **构建脚本**：`6_Editor/BuildMenu.cs`——菜单 `Card/Build/Windows x64` + 静态方法供 `-executeMethod` 批处理；输出 `Builds/Windows/CardReborn.exe`。
- **一键双开脚本**：`Tools/dual-launch.ps1`——启动两个构建实例（房主 `-host <port>` + 加入 `-join=127.0.0.1:<port>`）；参数可覆盖 exe 路径与端口；全文 ASCII（PowerShell 5.1 ANSI 坑）。
- **说明文档**：`Docs/HANDOFF.md` 新增"双开验证"小节：构建 → 一键双开（脚本）→ 编辑器 + 构建组合（编辑器手动当房主）→ 常见问题（端口占用、单实例日志定位）。
- `.gitignore` 已有 `/[Bb]uilds/` 忽略（核实无需增补）。

## 4. 明确不做（防止范围蔓延）

- **不做编辑器双实例**：同一工程不能双开编辑器（锁 `Library`，[05 §15.3](../05-联网对战_状态同步_设计文档.md) 已确认）；"编辑器 + 构建"组合中编辑器侧手动 Play。
- **不做端口 OS 随机分配**：双开验证需要地址可复现；解析器 `Port=0` 语义在接线层映射为默认 7777（`CommandLineRoleParser` 本体与其测试不动）。
- **不做自动出包流水线**：多平台、版本号、增量构建、签名、压缩包分发均不做。
- **不做局域网两台设备的网络环境说明**（防火墙/内网 IP 发现）——列入说明"已知限制"一句即可。
- **不碰 T5/T6/T7 范围**：对局结果记录、异常提示打磨、Soak 均为后续任务。

## 5. 接口约定

```csharp
namespace Card.Application.Launch
{
    public enum NetLaunchKind { None, Host, Join }

    /// <summary>启动参数解析出的联机大厅自动动作。</summary>
    public readonly struct NetLaunchAction
    {
        public NetLaunchKind Kind { get; }
        /// <summary>房主监听端口 / 加入端口（已应用默认端口）。</summary>
        public int Port { get; }
        /// <summary>加入目标地址（"host:port"，仅 Join 有效）。</summary>
        public string Address { get; }
    }

    public static class NetLaunch
    {
        /// <summary>args 为 null 时读 Environment.GetCommandLineArgs（跳过 exe 路径）。</summary>
        /// <param name="defaultPort">端口未在参数中指定时使用（Bootstrap 传 PvpLobbyFlow.DefaultListenPort）。</param>
        public static NetLaunchAction Resolve(int defaultPort, string[]? args = null);
    }
}
```

接线点（不新增类型，只改两处 `Start`）：

```csharp
// MainMenuBootstrap.Start：开头加
var action = NetLaunch.Resolve(Battle.BattleSceneBootstrap.PvpNetDefaultPort);
if (action.Kind != NetLaunchKind.None) { PlayerPrefs PVPNet + Log + LoadScene(Battle); return; }

// BattleSceneBootstrap.StartNetMode：大厅建好后
var action = NetLaunch.Resolve(PvpLobbyFlow.DefaultListenPort);
if (action.Kind == Host)  { /* 以 action.Port 构造 flow */ flow.CreateAsHost(); }
if (action.Kind == Join)  { flow.ConnectAsJoiner(action.Address); }
```

> `PvpNetDefaultPort`：`BattleSceneBootstrap` 新增常量 7777（主菜单无 PvpLobbyFlow 引用，经它转发），与 `PvpLobbyFlow.DefaultListenPort` 同值——Unity EditMode 侧加一致性测试断言两者相等（防漂移；kernel 集不含 Bootstrap 源，该断言放 `EditMode/Bootstrap/`）。

## 11. 结论（收尾回填）

### 11.1 交付物

- `2_Application/Launch/NetLaunch.cs`：启动参数 → 联机大厅自动动作（None/Host/Join），纯 BCL 进 kernel 口径；端口未指定映射调用方默认端口（7777 可复现地址）。
- `5_Bootstrap/Menu/MainMenuBootstrap.cs`：Start 接线——参数为 Host/Join 时设 PVPNet 直入 Battle，无参行为不变。
- `5_Bootstrap/Battle/BattleSceneBootstrap.Net.cs` + 新 `BattleSceneBootstrap.NetLaunch.cs`（partial，为守 R5 ≤300 行拆分）：`CreateNetLobby` 装配大厅 + `ApplyNetLaunchAction` 自动创建/连接；房主端口可由 `-host <port>` 覆盖；Join 自动回填地址输入框。
- `6_Editor/BuildMenu.cs`：菜单 `Card/Build/Windows x64` + `BuildWindowsForAutomation()` 批处理入口（MainMenu+Battle 显式场景清单；构建失败抛 `InvalidOperationException` → `-executeMethod` 退出码非 0）。
- `Tools/dual-launch.ps1`：一键双开（`-host <port>` + `-join=127.0.0.1:<port>`；`-Exe/-Exe2/-Port/-HostAddress` 可覆盖；全文 ASCII）。
- `Docs/HANDOFF.md` §4.3 双开验证指南（出包 → 一键双开 → 手动参数 → 编辑器+构建 → 日志定位 → 常见问题 → 已知限制）。
- `.gitignore` 核实已含 `/[Bb]uilds/`，未改动。
