## 2. 目标（一句话）

> 为 PVP 异步命令回路提供"表现先行"反馈机制：上行命令后本地立即呈现待确认视觉（不改本地状态），权威 step 到达后被接受则清除待确认视觉交由状态同步落位、被拒绝则回退视觉并浮出拒绝原因。

## 3. 范围（做什么）

- 新增 `Card.Application.Match.PendingCommandTracker`（纯 BCL）：在途命令登记簿。
  - `Track(int? seq)`：上行时登记（seq 缺省 = 无序号模式）。
  - `Resolve(StepOutcome)`：step 到达时裁决 → `Accepted`（含重复包命中时清除 pending）/ `Rejected(错误码, 明细)` / `None`（对手 step、未登记命令）；按 seq 精确匹配，无 seq 按 FIFO。
  - `Clear()`：快照重置 / 断线重连时清空（VersionGap 时不自行清空，由快照恢复方显式调用）。
- 新增 `Card.Presentation.Battle.Feedback.CardPendingView`（MonoBehaviour，仿 CardFadeOutView）：卡牌待确认可视副作用组件。
  - `ShowPending()`：半透明 + 上移偏移（"卡牌飞向战场"的即时反馈占位）。
  - `Rollback()`：恢复原位与 alpha（"卡牌飞回手牌"）。
  - `Confirm()`：清除待确认视觉，落位交由权威状态同步（BattleViewSynchronizer）驱动。
  - `Stop()`：无条件复位，供 `CardView.SetData` 复位路径与池归还调用。
- `CardView.SetData` 纳入复位路径（M6-T5 复用即全量复位契约）：复用前 Stop 待确认视觉。
- 新增 `Card.Presentation.Battle.Feedback.PendingActionFeedback`（纯 C# 协调器）：
  - `NotifySubmitted(int? seq, int? cardInstanceId)`：登记 pending + 对卡牌视图施加待确认视觉。
  - `NotifyStep(StepOutcome)`：经 tracker 裁决后驱动确认/回退；Rejected 时在卡牌位置浮出原因文字（复用 FloatingTextPool），并经 GameLog.Warn 留痕。

## 5. 接口约定

```csharp
// Card.Application.Match（纯 BCL）
public enum PendingResolutionKind { None = 0, Accepted = 1, Rejected = 2 }

public sealed class PendingResolution
{
    public static PendingResolution None { get; }
    public static PendingResolution Accepted { get; }
    public static PendingResolution Rejected(CommandError error, string detail);
    public PendingResolutionKind Kind { get; }
    public CommandError Error { get; }   // 仅 Rejected 有效
    public string Detail { get; }        // 仅 Rejected 有效
}

public sealed class PendingCommandTracker
{
    public int PendingCount { get; }
    public void Track(int? seq);                     // 登记在途命令
    public PendingResolution Resolve(StepOutcome outcome); // 权威步裁决
    public void Clear();                             // 快照重置/断线时清空
}
// 匹配规则：outcome.Seq 有值 → 与 pending 按 seq 精确匹配；outcome.Seq 为空 →
// 队头 pending 无 seq 时按 FIFO 命中最旧；混合（队头带 seq 而步无 seq）→ None 不动。
// Applied/DuplicateDiscarded 命中 → Accepted 并移除；Rejected 命中 → Rejected 并移除；
// VersionGap → None 且 pending 保留；空 pending / 无匹配 → None。

// Card.Presentation.Battle.Feedback（Unity，可 EditMode 测试）
public sealed class CardPendingView : MonoBehaviour
{
    public bool IsPending { get; }
    public void ShowPending();   // alpha 半透明 + 上移
    public void Rollback();      // 复位（回退）
    public void Confirm();       // 复位（确认落位）
    public void Stop();          // 无条件复位（SetData 复位路径）
}

public delegate bool CardViewLocator(int instanceId, out CardView? view);

public sealed class PendingActionFeedback
{
    public PendingActionFeedback(PendingCommandTracker tracker,
        CardViewLocator? locator, FloatingTextPool? texts);
    public void NotifySubmitted(int? seq, int? cardInstanceId);
    public void NotifyStep(StepOutcome outcome);
}
```

### 设计决策备注

- VersionGap 不消费 pending：命令是否已在权威侧生效未知，"不猜"原则（Docs/05 §5.2）——快照恢复（ApplySnapshot 重置基线）后由恢复方调 `Clear()`，pending 视觉随重渲染复位。
- 确认复位不改位置语义：接受后卡牌落位完全由权威增量（StateChangeApplier → BattleViewSynchronizer 重渲染）驱动，Confirm 仅清除占位视觉，避免表现层自作主张写位置。
