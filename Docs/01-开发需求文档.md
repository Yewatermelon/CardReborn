## 1. 产品定位

| 项 | 定义 |
| --- | --- |
| 一句话 | 以 PvE 为基础、可扩展至联网 PVP 的回合制集换式卡牌对战游戏，玩法对标《炉石传说》核心对局体验 |
| 玩法内核 | 法力水晶资源曲线 → 出牌 → 随从交换/英雄压制 → 生命归零定胜负 |
| 差异化 | 关卡化 PvE 冒险（章节 + Boss 特殊规则）+ 轻量收藏/合成养成 + 权威状态同步的联网 PVP |
| 目标平台 | PC（Windows，优先） → 后续可考虑移动端 |
| 单局时长 | 5–12 分钟 |
| 目标用户 | 卡牌游戏爱好者；同时作为可展示的完整作品集项目 |
| 成功标准 | 不依赖任何调试快捷键，玩家可从"启动 → 组卡 → 打完整一局 → 胜负结算 → 再战"闭环 |

### 1.1 范围边界

**阶段一（M0–M10，PVE 基础阶段）不做，但必须预留**

- **联网 PVP 对战**：网络结构为**权威宿主 + 状态同步（Server-Authoritative State Replication）**。**本阶段的目标收敛为"在单台 PC 上用监听服务器（房主模式）验证双人联网对战"**，即其中一个客户端进程充当权威宿主；专用服务器推迟到未来，详见 [05-联网对战(状态同步)设计文档](./05-联网对战_状态同步_设计文档.md) 第 2.4 与第 15 节。
- 因此本阶段**不需要**：专用服务器、匹配/排队服务、账号体系、NAT 穿透、中继、反作弊、客户端预测。
- 由于权威宿主（本阶段是房主客户端，将来是专用服务器）要**直接复用同一份规则代码**，阶段一必须保证 `Card.Core` / `Card.Domain` / `Card.Application` **只依赖 BCL、不引用 `UnityEngine`**（见 [03-开发规范文档](./03-开发规范文档.md) 第 5.9 节）。这是必须现在做、不能事后补的预留工作。
- 同时要求对局状态**可序列化、可裁剪、可增量**，状态变更统一产出 `GameEvent`；这是阶段二状态下发的数据结构前提。
- 阶段一不需要为了联网而限制浮点或要求跨平台逐位一致（这是此前帧同步方案的约束，已随方案变更一并撤销）。

**本项目明确不做**

- 好友、公会、聊天、排行榜等社交系统
- 内购、广告、真实货币经济
- 卡牌 3D 模型与复杂 VFX 特效（使用 2D 图 + Tween/简单 Shader）
- 多语言之外的语音配音
- 电竞级反作弊与强中立权威（本阶段不做任何反作弊；将来上专用服务器也只能到"中—高"，见 05 文档第 7 节）

### 1.2 阶段划分

| 阶段 | 里程碑 | 内容 | 优先级 |
| --- | --- | --- | --- |
| 阶段一 | M0–M10 | PVE 基础：规则内核、表现层、AI、元游戏、内容与打磨 | P0 |
| 阶段二 | M11–M14 | 联网 PVP：**本机房主模式验证**（共享内核、回环传输、权威状态同步、裁剪与重连） | P2（拓展） |
| 阶段三（未来） | 待定 | 专用服务器 / 公网对战 / 匹配服务 / 反作弊 / 预测与和解 | 暂不做，仅预留接口 |

> 阶段划分不改变重要性的判断：**阶段一是地基，阶段二是加层。** 阶段二能否低成本落地，取决于阶段一的规则代码是否与 Unity 解耦、状态是否可序列化。

## 2. 核心循环

### 2.1 元循环（Meta Loop，游戏外）

```
主菜单 → 选择/编辑卡组 → 选择关卡 → 进入对局
   ↑                                    ↓
   └── 获得金币/奖励 ← 胜负结算 ← 对局结束
              ↓
        商店抽卡 → 获得新卡 / 粉尘 → 合成卡牌 → 回到卡组编辑
```

### 2.2 对局循环（Match Loop）

```
开局（抽起手 / 定先后手 / 掷硬币）
  → [回合开始] 法力上限+1、法力回满、触发回合开始效果、抽 1 张
      → [出牌阶段] 循环：选择卡牌 → 选择目标 → 校验 → 结算 → 表现
      → [攻击阶段] 循环：选择随从 → 选择目标 → 校验（嘲讽/失调） → 交战结算
      → 主动结束回合
  → [回合结束] 触发回合结束效果
  → 判定胜负（英雄生命 ≤ 0 或 牌库空且疲劳致死）
  → 未结束则切换对手
  → 对手（AI）执行同样的循环
```

### 2.3 拓展阶段循环（联网 PVP，阶段二）

```
登录/进入大厅 → 创建或加入房间 → 双端就绪
  → 房主进程开启一局 MatchHost（权威内核），向双方下发 MatchStart 与各自视角的初始快照
  → 循环：客户端上行命令（我要出哪张牌/攻击谁）
          → 房主侧校验（回合、费用、目标、场位、嘲讽…）
          → 房主侧结算并生成事件与状态增量
          → 房主侧按玩家视角裁剪后下发
          → 客户端应用状态、播放表现（可先做本地表现反馈）
  → 回合切换、掉线重连（快照 + 增量）、超时判定
  → 胜负结算 → 本地记录 → 再来一局 / 返回主菜单
```

> 关键区别：PVE 阶段"客户端自己结算"，PVP 阶段"**只有权威宿主结算**"（本阶段即房主进程）。客户端上行的是**意图**，下行的是**权威侧产出的状态与事件**。
> 正因如此，阶段一必须把"意图 → 命令 → 校验 → 结算 → 事件"做成唯一规则入口（见 03 铁律 5、12），并把状态设计成可序列化、可裁剪的形式。

## 3. 对局规则规格（数值以本文为唯一真相）

### 3.1 基础参数表

| 参数 | 数值 | 说明 |
| --- | --- | --- |
| 英雄生命上限 | 30 | 双方独立 |
| 法力水晶上限 | 10 | 每回合 +1 直到 10 |
| 法力回复 | 回合开始回满 | 未用完不累积 |
| 卡组构筑张数 | 30 | 严格等于 30 |
| 同名卡上限 | 2（传说卡 1） | 校验时强制 |
| 起始手牌 | 先手 3 张 / 后手 4 张 + 1 张"幸运币" | 先手第 1 回合少抽 1 张（仅第 1 回合） |
| 手牌上限 | 10 | 超出则抽到的牌被"燃烧销毁"并播表现 |
| 战场随从上限 | 7 | 满场时不能召唤 |
| 攻击次数 | 每位随从每回合 1 次（风怒 2 次） | 回合开始重置 |
| 疲劳 | 牌库为空后每抽 1 张受 `疲劳计数` 点伤害，计数逐次 +1 | 抽牌即结算 |
| 胜负条件 | 英雄生命 ≤ 0 判负；先手方无法行动超时（可选）判负 | 平局：双方同时 ≤ 0 判平局 |

### 3.2 回合阶段（TurnPhase）

| 阶段 | 是否等待玩家 | 可执行操作 |
| --- | --- | --- |
| `MatchStart` | 否 | 掷先后手、抽起手、换牌（可选，P1 阶段实现） |
| `TurnStart` | 否 | 加水晶、回法力、重置攻击次数、触发 `OnTurnStart` |
| `Draw` | 否 | 自动抽 1 张（先手首回合除外）、结算疲劳 |
| `Main` | **是** | 出牌、攻击、使用英雄技能、结束回合 |
| `TurnEnd` | 否 | 触发 `OnTurnEnd`、清理临时增益 |
| `MatchEnd` | 否 | 结算胜负、发奖励 |

### 3.3 出牌规则

1. 卡牌费用 ≤ 当前可用法力，否则不可出。
2. **随从**：战场有空位才能召唤；召唤后进入"召唤失调"状态（当回合不能攻击），除非有 `冲锋`。
3. **法术**：按 `TargetRule` 决定是否需要目标；需要目标而玩家未选目标时不可确认。
4. **传说**：同名传说随从同时只能有 1 个在场。
5. 出牌顺序即结算顺序；战吼（`OnPlay`）在随从进场后触发。

### 3.4 攻击规则

1. 攻击者必须：在场上、未召唤失调、本回合剩余攻击次数 > 0。
2. **嘲讽**：只要敌方存在任意"嘲讽"随从，就必须优先攻击嘲讽随从（含英雄目标同样受限）。
3. 随从交换：**同时结算**，攻击方与防御方互相造成等同于自身攻击力的伤害。
4. 攻击英雄：仅英雄受到伤害，攻击方不受伤害。
5. 圣盾：抵消一次伤害后圣盾消失。
6. 伤害为 0 时仍视为一次攻击（消耗攻击次数）。
7. 生命 ≤ 0 的随从进入死亡结算：触发 `OnDeath` → 移入坟场 → 更新场面。

### 3.5 关键词（Keywords，首版必备）

| 关键词 | 标识 | 规则 | 优先级 |
| --- | --- | --- | --- |
| 嘲讽 | `Taunt` | 敌方必须优先攻击它 | P0 |
| 冲锋 | `Charge` | 召唤当回合即可攻击 | P0 |
| 圣盾 | `DivineShield` | 抵消下一次伤害 | P0 |
| 战吼 | `Battlecry` | 从手牌打出时触发一次 | P0 |
| 亡语 | `Deathrattle` | 死亡时触发一次 | P0 |
| 风怒 | `Windfury` | 每回合可攻击 2 次 | P1 |
| 潜行 | `Stealth` | 无法被选为目标；攻击后解除 | P1 |
| 剧毒 | `Poisonous` | 对随从造成伤害即摧毁 | P1 |
| 冻结 | `Frozen` | 跳过下一次攻击 | P1 |
| 突袭 | `Rush` | 当回合可攻击随从但不能攻击英雄 | P1 |
| 法术伤害 | `SpellPower` | 使法术伤害 +N | P1 |
| 吸血 | `Lifesteal` | 造成伤害时回复等量生命 | P2 |

### 3.6 英雄技能

- 默认英雄技能：**2 费，造成 1 点伤害**（目标：任意角色）。
- 每回合限用 1 次，回合开始重置。
- 不同英雄可有不同技能（P1 阶段引入，通过配置表定义）。

## 4. 卡牌效果规格

### 4.1 效果数据模型

每张卡 = `CardDefinition`（只读配置）+ 一组 `IEffectData`（可组合效果组件）。

```
CardDefinition
├─ Id                : int            唯一 ID，稳定不变
├─ Key               : string         稳定英文键（用于代码/资源引用）
├─ Name / Description: string         本地化键，如 CARD_001_NAME
├─ Cost              : int            法力消耗
├─ Type              : Minion|Spell|Weapon(预留)|Hero(预留)
├─ Rarity            : Common|Rare|Epic|Legendary
├─ Class             : Neutral|Mage|Warrior|...
├─ Attack / Health   : int            （随从）
├─ Keywords          : KeywordSet     关键词位标记
├─ TargetRule        : None|Any|Enemy|Friendly|EnemyMinion|FriendlyMinion|AnyMinion
├─ Effects           : IEffectData[]  战吼/亡语/法术效果
├─ ArtKey / AudioKey : string
└─ SetKey            : string         所属系列（用于关卡/卡池筛选）
```

### 4.2 效果组件清单（首版需实现）

| 效果组件 | 参数 | 触发时机 | 说明 |
| --- | --- | --- | --- |
| `DamageEffect` | amount, target | OnPlay / OnDeath / SpellResolve | 造成伤害 |
| `HealEffect` | amount, target | 同上 | 回复生命（不超过上限） |
| `DrawCardEffect` | count, targetPlayer | OnPlay / OnDeath | 抽牌（含爆牌与疲劳处理） |
| `BuffEffect` | attack, health, target | OnPlay | 增益随从（可给临时增益） |
| `SummonEffect` | cardKey, count, position | OnPlay / OnDeath | 召唤随从 |
| `DestroyEffect` | target | OnPlay / SpellResolve | 直接摧毁 |
| `GainManaEffect` | amount / overload | OnPlay | 获得临时法力（幸运币） |
| `GainArmorEffect` | amount, targetPlayer | OnPlay | 获得护甲 |
| `SilenceEffect` | target | OnPlay | 移除关键词与增益 |
| `DamageAllEffect` | amount, side | OnPlay | 群体伤害 |
| `ConditionalEffect` | condition, thenEffects, elseEffects | — | 条件效果（容器） |
| `CompositeEffect` | effects[] | — | 顺序组合容器 |

> **扩展要求**：新增一种效果 = 新增 1 个 `IEffectData` 实现 + 1 个执行器 + 配置字段，**不得修改已有卡牌代码**。

### 4.3 触发时机枚举（Trigger）

`OnPlay`（战吼）、`OnDeath`（亡语）、`OnTurnStart`、`OnTurnEnd`、`OnSummon`、`OnAttack`、`OnAttacked`、`OnDamageTaken`、`OnHeal`、`OnCardDrawn`、`OnSpellCast`。

## 5. 功能需求清单（FR）

> 优先级：**P0 = MVP 必须**；P1 = 完整体验需要；P2 = 加分拓展。
> 每条需求都有可执行的验收标准（AC），验收标准必须能被测试用例覆盖。

### FR-1 数据与配置（P0）

| 编号 | 需求 | 验收标准（AC） |
| --- | --- | --- |
| FR-1.1 | 卡牌数据由 Excel 配置表驱动 | 修改 Excel 后执行导入菜单，卡牌数据更新，无需改代码 |
| FR-1.2 | 配置导入带完整校验 | 非法值（负费用、空名、重复 ID、未知关键词/效果）导入时给出**明确错误行号**并终止，不产生半成品数据 |
| FR-1.3 | 支持热加载 | 编辑器下点击"重载配置"，运行中对局外的卡牌数据即时刷新，无需重启 |
| FR-1.4 | 运行时可用 id/key 双索引查询 | `CardDatabase.Get(id)` / `Get(key)` O(1)；查不到返回明确错误而非 null 崩溃 |
| FR-1.5 | 卡池按系列/稀有度筛选 | 可按 `SetKey`、`Rarity`、`Class` 组合筛选，用于抽卡与关卡 |
| FR-1.6 | 配置表版本号 | 导出的数据文件带 `schemaVersion`，与代码期望版本不匹配时给出警告 |

### FR-2 卡牌与收藏（P0）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-2.1 | 玩家收藏记录每种卡的数量 | 存档中 `{cardKey: count}`，重启后保留 |
| FR-2.2 | 收藏册 UI 展示全部卡牌 | 按费用/稀有度排序，未拥有的显示为灰色，显示拥有数量 |
| FR-2.3 | 卡牌详情面板 | 显示名称、费用、攻/血、关键词、描述文本与美术 |
| FR-2.4 | 粉尘与合成/分解（P1） | 分解得粉尘、合成消耗粉尘；传说/史诗/稀有/普通粉尘值可配置 |

### FR-3 卡组编辑（P0）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-3.1 | 可视化组卡 | 左右两栏（收藏 / 当前卡组），点击或拖拽增删 |
| FR-3.2 | 合法性校验 | 张数 = 30、同名 ≤ 2（传说 1）、未拥有不可加入；不合法时"保存/使用"置灰并提示原因 |

| FR-3.4 | 多套卡组 | 支持保存多套（P1），可命名、删除、设为主力 |
| FR-3.5 | 编辑态独立 | 未点保存前离开页面有"未保存"提示；取消可还原 |
| FR-3.6 | 保存与加载 | 卡组写入存档，重启后恢复 |

### FR-4 抽卡与商店（P0）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-4.1 | 金币消耗抽卡 | 每包 5 张，消耗金币（可配置），金币不足时按钮置灰并提示 |
| FR-4.2 | 稀有度权重 | 概率由配置表定义（如 普通 70% / 稀有 22% / 史诗 6% / 传说 2%），单包至少 1 张稀有以上 |
| FR-4.3 | 保底机制 | 连续 N 包（可配置，默认 10）无传说则第 N+1 包必出传说；计数存档 |
| FR-4.4 | 抽卡结果写入收藏 | 抽到的卡立即入收藏并即时保存 |
| FR-4.5 | 开包表现 | 逐张揭示，稀有度有差异化表现与音效，可点击跳过 |
| FR-4.6 | 随机可复现（调试） | 支持注入种子，同种子结果一致，用于平衡性测试 |

### FR-5 对战核心（P0，项目最重要的需求）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-5.1 | 完整回合状态机 | 阶段严格按 3.2 流转，非法阶段操作被拒绝且不改变状态 |
| FR-5.2 | 法力水晶系统 | 每回合上限 +1，回合开始回满，显示当前/上限 |
| FR-5.3 | 出牌流程 | 费用校验 / 目标校验 / 场位校验全部通过才结算 |
| FR-5.4 | 随从召唤 | 召唤失调、场面上限 7、传说唯一性 |
| FR-5.5 | 攻击流程 | 攻击次数、召唤失调、嘲讽强制、同时伤害结算 |
| FR-5.6 | 英雄与胜负 | 英雄 30 血，归零立即结算胜负并展示结算界面 |
| FR-5.7 | 死亡结算 | 生命 ≤ 0 → 触发亡语 → 移入坟场 → 更新场面与 UI |
| FR-5.8 | 手牌上限与爆牌 | 超过 10 张时抽到的牌被销毁并播表现 |
| FR-5.9 | 疲劳机制 | 牌库空后抽牌受递增伤害 |
| FR-5.10 | 英雄技能 | 2 费造成 1 点伤害，每回合 1 次 |

| FR-5.12 | 战斗日志 | 记录并展示关键事件（出牌、伤害、死亡、回合切换），可滚动 |

> 设计细节见 [05-联网对战(状态同步)设计文档](./05-联网对战_状态同步_设计文档.md)。本节只定义需求与验收标准。

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-14.1 | 本机直连 | 房主进程启动后显示监听地址与端口；玩家 2 填入地址即可连接（`127.0.0.1` 为主，可选局域网 IP）；**不做匹配/房间列表/排队** |
| FR-14.2 | 权威宿主 | 对局全部关键计算（校验、结算、随机）只在**权威宿主**执行；客户端上报的是意图，不认可客户端上报的任何状态 |
| FR-14.3 | 命令上行 | 客户端上行 `GameCommand`（含命令序号与目标回合）；权威侧校验后返回 `CommandAccepted` / `CommandRejected`（含拒绝原因） |
| FR-14.4 | 状态下行 | 权威侧下发状态增量（基于版本 + 新版本 + 变化列表 + 事件）；版本冲突或丢失时客户端请求全量快照 |
| FR-14.5 | 视野裁剪 | 权威侧按玩家视角生成状态：对手手牌只下发数量，牌库顺序不下发；客户端内存中不存在对手手牌明细 |
| FR-14.6 | 断线重连 | 断线后可通过"裁剪后的全量快照 + 增量"恢复到最新版本；重连超时按掉线判负 |
| FR-14.7 | 掉线与超时 | 房主退出 → 对局结束并给出明确提示；玩家 2 掉线 → 房主提示"对手掉线"并允许等待重连（默认 30 s）；回合操作超时可配置 |
| FR-14.8 | 客户端表现 | 操作即时反馈（表现先行），权威状态到达后落位；被拒绝时回退并提示原因；状态变化经插值播放 |
| FR-14.9 | 网络异常可诊断 | 日志记录 RTT、丢包、下行带宽、版本冲突、重连、命令拒绝原因；可导出诊断信息 |
| FR-14.10 | PVE 不受影响 | 联网代码位于独立程序集；断网、无法联机时 PVE 全部功能可正常运行与出包 |
| FR-14.11 | 宿主抽象 | 权威运行时 `MatchHost` 只实现一份，位于共享层；本阶段实现 `LocalHost`（PVE）与 `PeerHost`（房主模式），`DedicatedHost` 只留接口；切换宿主不需要改动规则代码 |
| FR-14.12 | 本机双人验证 | 同一台 PC 上两个进程（编辑器 + 构建，或两个构建）可完整跑完一局，双方画面一致、回合归属正确、玩家 2 看不到房主手牌内容 |
| FR-14.13 | 零新依赖 | 本阶段传输使用 BCL（`System.Net.Sockets`）+ 长度前缀消息，不引入任何第三方网络库；消息仍须带协议版本与字段校验 |
| FR-14.14 | 安全边界披露 | 明确标注本阶段不提供反作弊：房主可看到对手手牌、可修改状态；产物仅用于本机验证，不对外分发或用于公开对战 |

4. 表内不得出现行序依赖；代码一律通过 id/key 查询，**禁止 `list[index]`**。

## 8. 首版内容目标（Content Target）

| 项 | MVP 目标 | 完整体目标 |
| --- | --- | --- |
| 卡牌 | ≥ 30 张（随从 20 + 法术 10） | ≥ 60 张 |
| 稀有度分布 | 普通 16 / 稀有 9 / 史诗 4 / 传说 3 | 按 60 张等比扩展 |
| 英雄 | 2（各带 1 个技能） | 4 |
| 关键词 | 5（嘲讽、冲锋、圣盾、战吼、亡语） | 10 |
| 效果组件 | 8 | 12 |
| 关卡 | 3 | 15+（4 章） |
| AI 难度 | 1 | 3 |

**平衡性基线**：AI vs AI 各种族对局胜率落在 **45%–55%** 区间；平均对局 **8–12 回合**结束；单局出现"打脸速攻"与"控制"两种以上获胜路径。具体验证见 [02-开发计划步骤文档](./02-开发计划步骤文档.md) M9。

### 8.1 阶段二（本机房主模式联网验证）目标

| 项 | 目标 |
| --- | --- |
| 对战模式 | **本机双人 1v1 验证**（同一台 PC 两个进程）；局域网为可选项；不做公网对战 |
| 部署拓扑 | **只做 `LocalHost`（PVE）+ `PeerHost`（房主模式）**；专用服务器只留接口 |
| 连接方式 | 房主显示 `IP:端口`，玩家 2 手动填入直连；**无匹配、无房间列表、无账号** |
| 权威 tick | 10 Hz（可配置） |
| 同步方式 | 权威状态同步：命令上行 + 状态增量下行（含事件），必要时下发全量快照 |
| 延迟目标 | **本机回环 RTT ≤ 5 ms**；操作到权威确认 ≤ 100 ms；操作到本地表现反馈 ≤ 1 帧 |
| 反作弊 | **不做**。房主即对手，可看牌、可改状态，属已知且接受的限制，需在 UI 与文档中披露 |
| 传输 | BCL TCP + 长度前缀，**零新依赖** |
| 断线重连 | 裁剪快照 + 增量恢复；重连窗口默认 30 s |
| 带宽目标 | 单局下行总量 ≤ 150 KB；心跳 ≤ 0.3 KB/s |
| 一致性目标 | 本机双进程 20 局无"状态错乱"；所有异常都有明确终态与可诊断日志 |
| 工期 | 阶段二约 **10–16 人日** |

**阶段二前置条件（必须在阶段一完成）**

1. FR-13.1–FR-13.7 全部达标（内核与 Unity 解耦、无 Unity 可跑完整对局、状态可序列化/可增量、事件流完整）。
2. `Card.Core` / `Card.Domain` / `Card.Application` 只依赖 BCL，不引用 `UnityEngine`。
3. 所有玩家与 AI 操作走 `GameCommand`，且命令可序列化。
4. 状态变更统一产出 `GameEvent`（供表现层与状态下发共用）。
5. 网络层尚未实现时也要能跑"进程内客户端 ↔ 权威宿主"集成测试（`InMemoryTransport` 直连 `MatchHost`）——这是 PVP 联调的基础设施，属于 M11/M12；同一套测试应能被 `PeerHost` 与 `DedicatedHost` 复用。

> 说明：阶段一**不需要**为了实现联网而禁止浮点、禁止 `Time`、或要求跨平台逐位一致。这些是此前帧同步方案的约束，已随方案变更撤销（见 [05 第 14 节](./05-联网对战_状态同步_设计文档.md)）。

## 9. 需求验收总表与完成定义

### 9.1 项目整体完成定义（Definition of Done）

一个需求只有**同时满足**以下全部条件才算完成：

1. 代码符合 [03-开发规范文档](./03-开发规范文档.md)（含 asmdef 依赖方向、命名、文件行数限制）。
2. 有对应自动化测试并通过（Domain/Application 层必须；表现层至少 PlayMode 冒烟）。
3. 编译 0 error / 0 warning。

### 9.3 阶段二验收清单（本机房主模式验证）

**环境与流程**

- [ ] 同一台 PC 上两个进程可连接（编辑器 + 构建，或两个构建）
- [ ] 房主界面显示 `IP:端口`，玩家 2 填入后可进入准备状态
- [ ] 双方各看到自己的 3 张起手牌；**玩家 2 界面上看不到房主手牌内容**
- [ ] 完整打完 ≥ 20 局，双方画面一致、回合归属正确、无错乱、无假活

**权威与数据**

- [ ] 所有状态变更都能追溯到一条经房主校验的命令
- [ ] 玩家 2 侧修改本地数据（血量/法力/手牌）不影响对局结果
- [ ] 玩家 2 侧伪造非法/重复/越权/超频命令全部被拒且状态不变
- [ ] 版本冲突或消息异常后可通过快照恢复，不需要重启
- [ ] 房主手牌与牌库顺序不出现在任何下发给玩家 2 的数据中（含快照与重连数据）

**异常与边界**

- [ ] 玩家 2 掉线：房主提示"对手掉线"，重连窗口内可恢复
- [ ] 房主退出：对局结束并给出明确提示，不卡在"等待中"
- [ ] 双方回环 RTT ≤ 5 ms，操作到权威确认 ≤ 100 ms
- [ ] 双实例同时运行在本机 ≥ 60 FPS（低配机 ≥ 30 FPS 可接受）

**工程约束**

- [ ] 传输使用 BCL，未引入任何第三方网络库
- [ ] 未引入匹配服务、账号体系、NAT 穿透或中继
- [ ] 移除 `Card.Network` 程序集后项目仍可编译出包，PVE 功能不受影响
- [ ] 文档与 UI 均明确标注"本阶段不提供反作弊，仅用于本机验证"
