## 8. 问题与根因（5 Why）

### 现象 1：门禁报告违规，但退出码是 0

- Why1：`check.ps1` 的函数返回值被 `Format-Table` 的输出污染，`exit $array` 退化为 0；
- Why2：脚本重构时把"打印报告"和"返回退出码"混在同一个函数里；
- Why3：脚本自身从未被测过——只测过"规则对不对"，没测过"退出码对不对"；
- **根因**：**门禁缺少自检机制**（工具本身不在被验证范围内）。

改进：新增 `-SelfTest`（探针树 + 逐条断言），并把退出码纳入验证；本次已复验 `FAIL → exit 1`。

### 现象 2：一次"全绿"其实跑在过期 DLL 上

- Why1：Unity 的 Bee 缓存沿用了旧的 `csc.rsp` 参数，`Card.Core` 编译失败但 `ScriptAssemblies` 里仍是旧 DLL；
- Why2：批处理运行"有测试结果"被我当成"当前源码通过"；
- Why3：没有校验"这次运行确实重新编译了被改动的文件"；
- **根因**：**验证证据与源码版本的绑定关系没有被检查**。

改进：涉及构建配置（`csc.rsp` / asmdef / 包）的改动，必须做一次**清缓存干净验证**（删除 `Library/Bee` + `ScriptAssemblies`）；本轮已按此复验（`0 error / 0 warning / 228 passed`）。

### 现象 3：`Assets/csc.rsp` 里的注释导致 200+ 编译错误

- Why1：Unity 把 rsp 内容按空白拆分传给编译器，`#` 注释被当成源文件路径；
- Why2：我按通用 rsp 习惯写了注释；
- **根因**：**Unity 的 rsp 不是标准 MSBuild 响应文件**，其限制没有记录在项目文档中。

改进：`csc.rsp` 只保留编译开关；限制写入 [03 第 4 节第 10 条](../03-开发规范文档.md)。
