## 6. 问题与根因（5 Why）

### 现象 1：Unity 批处理 EditMode 验证自 T3 起静默失效（M3-B1）

- Why1：`-runTests` exit 0 但无结果文件；
- Why2：`EditorApplication.isUpdating` 恒真、主循环 `update` 不执行，测试调度器永不启动；
- Why3：TRAE 沙箱拦截 `bee\trash`、`upm.log` 等 Unity 构建系统写入；
- **根因**：**AI 执行环境对 Unity 构建管线的沙箱限制不可绕过**，不是工程代码问题。
- 改进：确立"无 Unity 工具链 = 权威验收口径"（用户决策）；.meta 手写规范（标准 MonoImporter + GUID 全仓去重）；M3-B1 挂 P2。**后续（同日）**：用户在编辑器 Test Runner 手动补验 608/608 全过，M3-B1 解除；经验——批处理被环境阻塞时，"编辑器手动跑 + 结果回填"是有效的补验路径。

### 现象 2：Rules 表扩列引发 ConfigValidator 5 个隔离 fixture 连带失败（T5）

- Why1：新外键校验（幸运币必须存在）对全部测试生效；
- Why2：缺列时 `OptionalTextOrDefault` 回落默认值 `"NEUTRAL_THE_COIN"`，等于"没配置也校验"；
- **根因**：**缺列回落默认值 + 全局外键校验组合出隐式耦合**——校验器校验的是回落值而非显式配置。
- 改进：缺列 → `TheCoinCardKey = null` → 跳过外键校验；仅显式配置才校验（真实 CSV 显式配置，生产链路不受影响）。

### 现象 3：NUnit `Assert.Throws<T>` 断言失败且报 nullable warning（T9）

- Why1：`Throws<T>` 要求精确类型，不匹配派生类；
- Why2：NUnit 约束的可空标注与 kernel 工程 `Nullable enable` 冲突；
- **根因**：**对断言库语义凭印象使用，未验证**。
- 改进：异常断言改 try/catch + `Assert.Fail`；经验已写入 T9 任务卡 §10.4。

### 现象 4：凭记忆调用 `Zone.Contains(int)` 编译失败（T10）

- Why1：直接写测试中的调用，未先确认目标类型 API；
- **根因**：**写调用先于读签名**。
- 改进：写调用前先 grep 目标类型公开成员；本次会话即时修正，未进提交历史。
