## 6. 问题与根因（5 Why）

### 现象 1：GameLog 静态状态跨测试泄漏，Unity 中参数化用例被静默跳过（T7）

- Why1：Unity EditMode 实跑数低于预期（728 而非更多），GameLog 参数化用例被跳过；
- Why2：`GameLog.ResetForTests()` 未归零 `SinkFailureCount`/`LastSinkFailure`；
- Why3：M1 设计 Reset 时只考虑了订阅/开关状态，没把故障计数字段纳入重置契约；
- **根因**：**静态门面的"测试重置"契约没有与其全部可变状态同步维护**——新增字段时无清单约束。
- 处置：`fix(core)` 提交 `c6df245` 独立修复（不顺手塞进 feat），Unity 补验恢复；经验——静态类加字段时必须同步检查测试重置入口。

### 现象 2：phase 字段两种 JSON 编码，Applier 初版只收字符串（T10）

- Why1：疲劳整局集成测试首跑 `FormatException: phase 必须是字符串枚举名，实际 Number`；
- Why2：`MatchStateSerializer` 快照写枚举**名字符串**，`MatchStateDiffer` 增量写 `(int)Phase` **数字**，Applier 初版按快照口径只解析字符串；
- Why3：两个生产者在 M3-T9/T10 各自定型时没有共享"线上传输统一编码"的契约测试；
- **根因**：**同一逻辑字段存在两套线上形状而无单一事实源**——单测各自通过，只有端到端整局链路能暴露。
- 处置：Applier 兼容字符串/数字两种编码（向前容错）；登记 **M4-OBS-1**：阶段二正式传输协议（M11/M13）必须统一枚举编码并加跨组件契约测试，禁止长期双格式共存。

### 现象 3：StateChangeApplier 初稿 372 行触发 R5 门禁（T10）

- Why1：`check.ps1` 报单文件 >300 行；
- Why2：路径解析 + 值校验 + 应用逻辑集中一类；
- **根因**：**设计期行数估算不足**，partial 拆分预案未提前定。
- 处置：拆为 `StateChangeApplier.cs`（应用主逻辑 202 行）+ `StateChangeApplier.Paths.cs`（解析/校验 162 行），门禁转绿；M3 已有 MatchStateSerializer 三拆先例，本次复用同款模式。

### 现象 4：凭记忆写枚举名/using，编译红两次（T10）

- Why1：测试写 `TurnPhase.MainPhase`（实际 `Main`）；ManaPool 漏 `using System;`（ArgumentOutOfRangeException 找不到）；
- Why2：写代码前未读目标签名（M3 复盘现象 4 的同类复发）；
- **根因**：**"写调用先于读签名"的旧习惯在赶进度时回潮**。
- 处置：编译红即时修正，未入提交；M3 已总结过一次，本里程碑再次出现——升级为流程动作（见第 8 节）。

### 现象 5：版本测试自身建模错误，拒绝命令被接受（T10）

- Why1：`Version_EqualsAcceptedCommandCount` 断言"非行动方拒绝"，实际版本 +1；
- Why2：首条 EndTurn 已使行动方轮换，测试仍按轮换前的座位关系构造"非法"命令，该命令此时恰好合法；
- **根因**：**测试构造依赖了前序命令改变的状态，却按初始状态推演预期**。
- 处置：改为由"原行动方在轮换后再发命令"构造真实 NotYourTurn 场景，并断言 error 码；测试意图更清晰。
