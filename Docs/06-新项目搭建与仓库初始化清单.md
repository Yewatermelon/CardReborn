# 06 新项目搭建与仓库初始化清单

> 版本：1.0 ｜ 状态：可执行清单（Checklist）
> 用途：把开发环境从**旧工程**（`E:\Unity\Project\Card`，即本目录）切换到**全新工程**，并把本套文档带过去，让开发可以立刻开始。
> 上游依据：[00-现状解构与架构再设计](./00-现状解构与架构再设计.md)、[02-开发计划步骤文档](./02-开发计划步骤文档.md) M0、[03-开发规范文档](./03-开发规范文档.md) 第 2 节

## 0. 先回答一个关键问题

> **"新建 Unity 工程 + 把文档拷过去" 是必要动作，但不充分。**

还差三类工作，否则新工程会在第一天就偏离规范：

1. **工程基线要对齐**（Unity 版本、模板/渲染管线、包、项目设置、TMP 资源）——否则文档里写的技术前提不成立。
2. **`_Project/` 目录骨架与 asmdef 要先建起来**——否则新写的脚本会全部落到 `Assembly-CSharp`，依赖方向约束形同虚设。
3. **旧代码不能直接拷进新工程**——旧脚本里有运行时引用 `UnityEditor` 的代码，放进 `Assets/` 会被 Unity 编译，导致新工程一开局就有编译错误（详见第 2.3 节）。

## 1. 应该新建工程，而不是在旧工程上改

推荐做法：**新开一个工程目录，旧工程原样保留作为参考。**

| 项 | 建议 |
| --- | --- |
| 旧工程 | `E:\Unity\Project\Card` —— **保留不动**，作为功能与数值的参考实现 |
| 新工程 | 建议 `E:\Unity\Project\CardReborn`（或你习惯的名字），**全新创建** |
| 新仓库 | 新工程目录内初始化（或克隆后把工程放进去），见第 4 节 |

> 好处：旧工程随时能打开对照（尤其是规则数值、UI 布局、美术资源），新工程从零开始、不受历史污染；M10 之前不需要删旧工程。

## 2. 新 Unity 工程怎么建

### 2.1 版本与模板（必须对齐）

| 项 | 要求 | 理由 |
| --- | --- | --- |
| Unity 版本 | **2022.3.x LTS**（与旧工程同为 `2022.3.54f1` 最省事；同 LTS 的其他补丁版本也可） | 文档中的包版本（TMP 3.0.7、Test Framework 1.1.33）、`activeInputHandler` 行为等前提均基于 2022.3。**不要用 Unity 6**，否则需要先更新文档的技术基线 |
| 模板 | **2D（Built-In Render Pipeline）** | 文档假设使用 Built-in 渲染管线（无 URP/HDRP 依赖）；选 URP 会让文档的渲染相关描述失效 |
| 工程类型 | 独立 Windows 桌面工程即可 | 不需要模板自带的教学场景或样例资源 |

> 如果 Unity Hub 里没有 2022.3.54f1，装一个同 LTS 的补丁版本即可；若你更想用 URP 或 Unity 6，**先告诉我**，我会同步更新文档的技术基线与包清单，避免文档和工程不一致。

### 2.2 建完工程后立刻要做的设置

| # | 设置 | 位置 | 值 / 动作 |
| --- | --- | --- | --- |
| 1 | 导入 TMP 资源 | Window → TextMeshPro → Import TMP Essential Resources | 必须导入一次，否则 TMP 文本不显示 |
| 2 | 公司名 / 产品名 | Project Settings → Player | 改成正式名称（存档路径与打包都会用到） |
| 3 | 默认分辨率 | Project Settings → Player → Resolution and Presentation | 1920×1080，允许窗口化 |
| 4 | API 兼容级别 | Project Settings → Player → Other Settings | `.NET Standard 2.1`（与文档的 BCL 约束一致） |
| 5 | 输入系统 | Project Settings → Player → Active Input Handling | `Input Manager (Old)`（文档 05 未依赖新输入系统；如要切新输入，需同步更新文档） |
| 6 | 分包/项目设置 | Project Settings → Editor | 序列化模式保持默认（Force Text），便于 diff |
| 7 | 包清理（可选） | Package Manager | 可移除 `Visual Scripting`、`Collab Proxy` 等本项目不用的包，减小体积 |
| 8 | 2D 相关包 | Package Manager | 若模板未包含，按需加 `com.unity.feature.2d`（图集/2D 工具会用到） |

> **不要**从旧工程拷 `ProjectSettings/`、`Packages/`、`Library/`、`obj/`、`.vs/`、`*.csproj`、`*.sln`。
> 这些是工程级配置与缓存，跨工程拷贝会带来 GUID 冲突、缓存错乱和无法解释的编译问题。包按第 2.2 表的清单在新工程里重新装一遍即可。

### 2.3 旧工程的哪些东西可以拷 / 不能拷

| 内容 | 处理 | 说明 |
| --- | --- | --- |
| `Docs/`（本套文档） | ✅ **必须拷** | 拷到新工程根目录（与 `Assets/` 同级） |
| `AGENTS.md` | ✅ **必须拷** | 放在新工程根目录 |
| 美术资源（如 `2D Casual UI`） | ✅ 可以拷 | 建议放 `Assets/_Project/Art/`；注意素材授权（见第 4.4 节） |
| 旧 `Assets/Scripts/*.cs` | ❌ **不要拷进 `Assets/`** | 旧脚本在运行时引用了 `UnityEditor`（`BattleManager.cs`、`PlayerData.cs`），放进 `Assets/` 会被编译，新工程一开局就报错；且这些代码整体废弃 |
| 旧 `Assets/Scenes/*.unity`、`Assets/prefabs/*` | ❌ 不建议拷贝 | 它们引用了旧脚本，拷过去全是 Missing Script 警告，价值低 |
| 旧 `Assets/Data/*.csv` | ⚠️ 仅作数值参考 | 不要当正式配置源；新工程用 Excel → 导入管线，把旧数值手工核对后写进新配置表 |
| `Assets/TextMesh Pro/` | ❌ 不要拷 | 新工程导入 TMP Essentials 即可；跨工程拷贝会造成 GUID 冲突与重复资源 |
| `Library/`、`Temp/`、`obj/`、`Logs/`、`UserSettings/` | ❌ 不要拷 | 纯缓存，必须重建 |

**如果确实想保留旧代码供查阅**：把它作为**纯文本参考**放在 `Assets/` 之外，例如
`Docs/reference/legacy-scripts/BattleManager.cs.txt`（改扩展名 → Unity 不会编译），
或干脆保留旧工程目录不删，需要时打开对照。**不要**放进 `Assets/` 下的任何目录。

## 3. 新工程目录骨架（M0-T2 要建的）

```
CardReborn/
├─ Assets/
│  ├─ _Project/
│  │  ├─ 0_Core/             Card.Core
│  │  ├─ 1_Domain/           Card.Domain
│  │  ├─ 2_Application/      Card.Application
│  │  ├─ 2_Network/          Card.Network（阶段二用，M0 先建空程序集）
│  │  ├─ 3_Infrastructure/   Card.Infrastructure
│  │  ├─ 4_Presentation/     Card.Presentation
│  │  ├─ 5_Bootstrap/        Card.Bootstrap
│  │  ├─ 6_Editor/           Card.Editor（仅 Editor 平台）
│  │  ├─ 7_Tests/
│  │  │  ├─ EditMode/        Card.Tests.EditMode
│  │  │  └─ PlayMode/        Card.Tests.PlayMode
│  │  ├─ Art/  Audio/  Prefabs/  Scenes/
│  │  └─ Config/             由 Excel 导出的 JSON / SO（生成物，勿手改）
│  └─ ThirdParty/            第三方资源原样放置
├─ Config/                   ★ Excel 配置源表放这里（Assets 之外）
│  └─ Excel/                 Cards.xlsx、Heroes.xlsx、Gacha.xlsx …
├─ Server/                   （未来）专用服务器，本阶段不建立
├─ Tools/                    check.ps1 等本地脚本
├─ Docs/                     本套文档
├─ AGENTS.md
├─ README.md
└─ .gitignore
```

> **为什么 Excel 放在 `Assets/` 之外**：Unity 会把 `Assets/` 下的 `.xlsx` 当成资源导入并生成 `.meta`，
> 既污染工程视图，也容易在构建时被打进包体。源表放仓库根的 `Config/Excel/`，导出结果写进 `Assets/_Project/Config/`，
> 这样"策划改表 → 工具导入 → 运行时读生成物"的链路最干净。

## 4. Git 与 GitHub

### 4.1 顺序（推荐）

```
1) 在 GitHub 建一个空仓库（不勾选 README / .gitignore / license）
2) 在本机新工程目录里初始化并绑定远程
3) 生成 .gitignore（Unity 模板 + 本项目补充）
4) 首次提交（只含工程骨架 + Docs + 配置源表）
5) 推送
```

### 4.2 需要你提供的信息

只需要两样：

1. **仓库地址**（HTTPS 或 SSH，例如 `https://github.com/<你>/<仓库名>.git`）
2. **可见性**：建议 **Private**（原因见 4.4）

> 创建仓库时**不要**勾选 "Add a README file" / ".gitignore" / "license"，
> 否则本地首次提交会与远程历史冲突（虽然能解决，但没必要）。

### 4.3 推送由谁来做

| 方式 | 说明 |
| --- | --- |
| 机器上已配置好凭据（推荐先试这个） | 我可以在本地完成 `git init` → 提交 → `git remote add` → `git push`；推送需要联网，我会先征求你的同意 |
| 你手动推送 | 我把本地仓库和首个提交做好，你执行 `git push -u origin main` 并输入凭据 |
| 使用 GitHub CLI | 你先执行 `gh auth login` 完成登录，之后我就能像第一种方式一样操作 |

> **不要把访问令牌（token）直接发给我**。用系统的凭据管理器或 `gh auth login` 授权即可，避免密钥落到聊天记录里。

### 4.4 仓库可见性：建议 Private

- 项目里的美术资源（如 `2D Casual UI`）如果来自 Unity Asset Store 或第三方素材包，其授权通常**不允许把原始素材公开发布**在公开仓库里。
- 建议：仓库设为 **Private**；若将来要开源，先把第三方素材剔除或替换，并补一份 LICENSE。

### 4.5 是否要用 Git LFS

| 情况 | 建议 |
| --- | --- |
| 只有少量图标 / 少量音频 | 可先用普通 Git，注意单文件不要超过 100 MB（GitHub 限制） |
| 有较多 PNG / PSD / WAV / 大 Excel | **建议启用 Git LFS**（在首次提交前配置，避免历史膨胀） |

需要的话，我可以在 M0 一开始就把 `.gitattributes`（LFS 规则）配好。

### 4.6 仓库地址要不要写进开发文档

建议：**写，但只写在一个地方**。

| 位置 | 是否写 | 理由 |
| --- | --- | --- |
| 仓库根 `README.md` | ✅ **写这里** | 仓库信息、Unity 版本、如何打开工程、如何跑测试，属于"项目入口信息" |
| `Docs/03-开发规范文档.md` 第 12 节（分支模型） | ⚠️ 可选 | 该节讲协作流程，补一行"远程仓库：`<url>`"也合理 |
| `Docs/01-开发需求文档.md` / `02` / `04` | ❌ 不要写 | 这些是需求与流程规格，与代码托管在哪无关；写进去以后换仓库还要改规格文档 |
| `AGENTS.md` | ❌ 不要写 | AI 在本地工作目录里作业，不需要远程地址 |

> 原则：**托管信息属于"项目入口"，不属于"开发规格"。** 换仓库不应该导致需求文档失效。

- [ ] 新工程能编译、能出包（空场景）
