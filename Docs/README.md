# 项目文档中心 / Docs Hub

本目录是 `Card`（炉石传说式回合制卡牌对战）项目唯一的**权威开发依据**。
任何人类开发者或 AI Agent 在对本项目做任何改动前，必须先阅读本目录文档。

> 规则：**代码与文档冲突时，以文档为准，并立即修正代码或提交文档变更提案（ADR）。**
> 文档不允许"过时不管"：改需求就改 `01`，改计划就改 `02`，改约定就改 `03`，改评审方式就改 `04`。

## 2. 本项目的四条不可违背的主线

1. **一切皆组件，组件优于继承。**
   卡牌的能力由"效果组件数据 + 效果执行器"组合而成，不得用 `class FireballCard : Card` 这类继承表达玩法。

2. **逻辑与表现分离，规则可离线单测。**
   领域层（`Card.Domain`）是纯 C#，不引用 `UnityEngine`；表现层只做"读状态 + 播表现"，不做规则判断。

3. **数据驱动，配置与代码解耦。**
   数值、效果、卡池、关卡全部来自配置表；新增卡牌原则上**只改配置不改代码**，改完后可热加载验证。

4. **规则内核与 Unity 解耦（为权威状态同步预留）。**
   阶段一只做 PVE；阶段二用**本机房主模式**（其中一个客户端充当权威宿主）验证联网，将来再切专用服务器。
   因此权威宿主（房主客户端 / 未来的服务器进程）要直接复用同一份规则源码，
   因此 `0_Core` / `1_Domain` / `2_Application` **只允许依赖 BCL**，且对局状态必须可序列化、可裁剪、可增量。
   这条约束**现在就必须遵守**，事后改造成本极高。
   详见 [03 第 5.9 节](./03-开发规范文档.md) 与 [05 联网对战设计](./05-联网对战_状态同步_设计文档.md)。

## 3. 使用方式（AI Agent 每次任务的固定动作）

```
1) 读 Docs/00、Docs/01 中与本任务相关的章节
2) 读 Docs/03 的"铁律 + 禁止清单 + 代码模板"
   —— 若触及规则层，必须读 Docs/03 第 5.9 节（内核解耦与状态序列化）；若触及联网，必须读 Docs/05
3) 在任务卡（templates/TaskCard.template.md）中写清楚：目标 / 范围 / 不做项 / 验收标准 / 涉及文档
4) 先写或补测试 → 再实现 → 本地跑通 → 自检（Docs/04 第 7 节提示词）
5) 按 Docs/04 的模板输出评审结论与证据
6) 若改动触及需求/计划/规范，同步更新对应文档，并在提交信息中注明
```

## 4. 术语速查

| 术语 | 含义 |
| --- | --- |
| Definition（定义） | 只读配置，来自 Excel/ScriptableObject，如 `CardDefinition` |
| Instance（实例） | 一局对局中某张卡的具体状态，如 `CardInstance`（当前攻击/生命/关键词） |
| Zone（区域） | 卡牌所在位置：牌库 Deck / 手牌 Hand / 战场 Board / 坟场 Graveyard |
| Effect（效果） | 可组合的卡牌能力单元（战吼、亡语、伤害、抽牌…） |
| Trigger（触发） | 效果被激活的时机枚举，如 `OnPlay`、`OnDeath`、`OnTurnStart` |
| Agent（玩家代理） | 决策来源的统一抽象，人类与 AI 都实现 `IPlayerAgent` |
| Match（对局） | 一次完整战斗，从开局到分出胜负 |
| 规则内核（Rule Kernel） | `Card.Core` / `Card.Domain` / `Card.Application` 三层，零 Unity 依赖，客户端与服务器共用 |
| 权威宿主（Authoritative Host） | 全局唯一的规则实例所在处：专用服务器进程，或房主模式的某个客户端进程 |
| 房主模式（Peer Host / Listen Server） | 用其中一个玩家的客户端充当权威宿主；零运维，但房主可看到对手手牌 |
| 命令（GameCommand） | 玩家的"意图"，如"出第 3 张手牌指向对方随从 2"；人类与 AI 共用 |
| 状态快照 / 增量（Snapshot / Delta） | 服务器下发的完整状态（用于首次进入与重连）与变化补丁（常规下发） |
| 视野裁剪（View Projection） | 服务器按玩家视角裁剪状态，对手手牌只下发数量 |
| 状态版本（StateVersion） | 单调递增的版本号，用于识别重复包、乱序与丢失 |
| 服务器 tick | 服务端推进节奏，默认 10 Hz；与客户端渲染帧率无关 |
| 阶段一 / 二 / 三 | 阶段一 = M0–M10（PVE 基础）；阶段二 = M11–M14（**本机房主模式联网验证**）；阶段三 = 专用服务器 / 公网 / 匹配 / 反作弊（暂不做） |
